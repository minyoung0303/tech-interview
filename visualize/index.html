이 아홉 주제는 서로 이어져 있습니다.

인덱스가 없으면 락 범위가 넓어져 데드락이 나고 → 락을 오래 잡으면 커넥션 풀이 마르고 → 그래서 결제는 트랜잭션 밖에서 멱등하게 처리해야 하고 → 그 앞단에는 재시도를 하는 프록시가 있고 → 배포 중에는 구·신 버전이 같은 DB를 동시에 봅니다.

인프라 4종은 그 뒤를 잇습니다. 트래픽이 늘어 Scale-out을 하면 앞에 로드 밸런서(L4/L7)가 필요하고 앱이 stateless여야 하니 세션을 Redis로 빼거나 JWT를 씁니다 → 똑같은 서버를 여러 개 찍어내려면 컨테이너가 필요하고 → 그것들을 VPC의 Private Subnet에 두고 앞단에만 ALB를 노출하고 → 교체는 무중단 배포로 하고 → 앱을 늘리면 병목은 결국 DB로 내려가 Read Replica와 샤딩을 판단하게 됩니다.

한 주제만 파는 것보다 이 연결을 말하는 쪽이 훨씬 강합니다.
